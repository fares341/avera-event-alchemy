# Build AVERA Event House Website

## Overview
Create a complete multi-page AVERA website in the selected Architectural Dossier direction: warm linen backgrounds, crisp white surfaces, muted cognac accents, Sora/Manrope typography, cinematic event imagery, and editorial pacing.

## Pages and navigation
- Build a shared sticky header, mobile menu, contact actions, footer, and persistent WhatsApp control.
- Create dedicated pages for Home, Corporate Events, Portfolio & Case Studies, Luxury Weddings, Methodology, Venues & Production, and Contact.
- Include the six corporate event categories in the Corporate Events navigation menu.
- Give every page distinct search and social metadata.

## Home and portfolio experience
- Build the requested corporate-first hero, client marquee, three core pillars, four-step process, specialist services, and wedding preview.
- Present the five supplied case studies using cinematic imagery and clear project details.
- Add an interactive Blueprint to Reality comparison for the UNIVAL gala.

## Inquiry experiences
- Build a three-step corporate booking wizard covering scope, services, company credentials, file selection, validation, review, and success confirmation.
- Build the complete wedding consultation form with the Arabic privacy notice, all requested fields, validation, and success confirmation.
- Open each form from the relevant calls to action without leaving the page.

## Visual assets and polish
- Generate a cohesive set of event and wedding images matching the selected warm editorial art direction.
- Use responsive layouts for desktop and mobile, restrained motion, accessible labels, keyboard-friendly dialogs, and reduced-motion support.
- Verify the site visually at desktop and mobile widths, including navigation, forms, comparison slider, and all page links.

## Technical details
- Use TanStack Router for every public page and typed links throughout.
- Keep visual values in the shared design-token system and use reusable controls for links, buttons, dialogs, fields, and cards.
- Keep submissions as front-end confirmations because no destination email, CRM, or persistence service was requested.
